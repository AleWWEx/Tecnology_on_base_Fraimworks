# Система организации дискуссионных клубов

## 1. Назначение

Автоматизация и оптимизация процессов управления дискуссионными клубами: от
создания мероприятий и регистрации участников до модерации дискуссий и сбора
обратной связи. Система призвана заменить рутинные и децентрализованные
методы организации (чаты в мессенджерах, электронные таблицы) на единую,
удобную и прозрачную платформу.

## 2. Целевая аудитория

* **Участники дискуссий** (студенты, школьники, взрослые энтузиасты): для поиска
  интересных тем, удобной записи на встречи и отслеживания своей активности.
* **Организаторы и администраторы клубов**: для управления расписанием,
  формирования списков участников и модерации сообщества.
* **Модераторы и спикеры**: для управления ходом конкретной дискуссии и оценки
  активности участников.
* **Образовательные учреждения** (вузы, школы): для курирования, поддержки и
  анализа внеучебной активности студентов и учеников.

## 3. Описание предметной области

Предметная область охватывает деятельность сообществ, практикующих
структурированные дискуссии (дебаты, круглые столы, философские кафе,
книжные клубы).

В настоящее время организация таких мероприятий часто ведётся вручную или с
помощью разрозненных инструментов (социальные сети, мессенджеры,
Google-таблицы). Это приводит к ряду проблем:

* потеря информации о расписании и правилах клуба;
* сложности с учётом посещаемости и формированием списков;
* отсутствие системы рейтингования или учёта вклада участников;
* неудобство поиска мероприятий по конкретным темам или уровням подготовки.

Разрабатываемая система решает эти проблемы, обеспечивая централизованное
хранение данных, ролевое разделение доступа и удобный интерфейс для
взаимодействия всех сторон.

## 4. Основные сущности

* **Пользователь (User):** физическое лицо, использующее систему. Имеет роль
  (Участник, Модератор, Администратор), профиль и историю активностей.
* **Дискуссионный клуб (Club):** сообщество с собственным названием,
  описанием, правилами и закреплёнными организаторами.
* **Тема дискуссии (Topic):** предмет обсуждения с описанием, тегами, уровнем
  сложности и рекомендуемой литературой и материалами.
* **Мероприятие (Event):** конкретная сессия дискуссии, привязанная к клубу и
  теме. Включает дату, время, место (или ссылку на онлайн-комнату), лимит
  участников и статус (планируется, идёт, завершено).
* **Регистрация (Registration):** связь между пользователем и мероприятием со
  статусом (ожидает подтверждения, подтверждён, присутствовал, отменён).
* **Отзыв/оценка (Feedback):** текстовый или числовой отзыв участника о
  мероприятии или организаторе после его завершения.

## 5. Основные функции

### Для участников:

* регистрация, авторизация и редактирование личного профиля;
* просмотр каталога клубов и предстоящих мероприятий с фильтрацией (по дате,
  теме, формату: онлайн/офлайн);
* подача заявки на участие в мероприятии и получение уведомлений о статусе
  заявки;
* оставление отзывов и оценок после посещения мероприятия.

### Для организаторов и администраторов:

* создание и редактирование профилей клубов и карточек тем дискуссий;
* планирование расписания мероприятий и управление заявками участников
  (подтверждение, отклонение);
* модерация контента (удаление некорректных тем или комментариев);
* просмотр базовой аналитики (посещаемость мероприятий, активность
  участников).

## 6. План развития

### По этапам функционала

* **Этап 1 (MVP — минимально жизнеспособный продукт):** базовая регистрация,
  создание клубов и мероприятий, функционал записи участников, простой
  интерфейс администратора.
* **Этап 2 (улучшение UX и коммуникации):** система рейтингов и достижений
  (геймификация), уведомления через Telegram-бот или Email, экспорт списков
  участников в PDF и Excel.
* **Этап 3 (масштабирование и онлайн-формат):** встроенный чат для обсуждения
  тем до встречи, интеграция с видеосервисами (Jitsi, Zoom), адаптивная
  мобильная версия (PWA).
* **Этап 4 (аналитика и AI):** расширенная аналитика для организаторов
  (тепловые карты активности, подбор тем на основе интересов пользователя с
  помощью рекомендательных алгоритмов).

## 7. Текущее состояние (ПР1)

На ПР1 реализован один законченный сценарий предметной области —
**«Запись участника на мероприятие дискуссионного клуба»**.

Программа формирует карточку мероприятия, определяет его статус по дате,
считает свободные места, проверяет требования к участнику (возраст, уровень
подготовки, чтение рекомендованных материалов) и принимает решение по заявке:
подтверждает, отправляет в лист ожидания или отказывает.

Использованные конструкции Python: простые типы данных, операции,
преобразование типов, ветвления (`if`, `if-else`, `if-elif-else`, составные
условия, логические операторы `and`, `or`, `not`), функции, импорт модулей
(`import datetime`, `from random import randint`).

### Реализованные функции

| Функция                     | Назначение                                                |
|----------------------------|-----------------------------------------------------------|
| `get_event_status`         | Определяет статус мероприятия: планируется, идёт, завершено |
| `get_free_places`          | Считает свободные места, не позволяя отрицательное значение |
| `check_requirements`       | Проверяет требования мероприятия, возвращает причину отказа |
| `get_registration_result`  | Принимает решение по заявке и формирует пояснение         |
| `generate_ticket_code`     | Создаёт код участия вида `DC-4821`                        |
| `get_event_card`           | Формирует текстовую карточку мероприятия                 |
| `process_application`      | Обрабатывает заявку, преобразует типы, печатает решение  |
| `run_demo`                 | Автоматическая демонстрация сценария на четырёх заявках   |
| `run_interactive`          | Диалоговый режим регистрации участника                    |
| `main`                     | Точка входа, выбор режима работы                         |

## 9. Как запустить

```bash
# Активировать виртуальное окружение
source .venv/Scripts/activate        # Windows Git Bash
# .venv\Scripts\activate              # Windows CMD
# source .venv/bin/activate          # Linux / macOS

# Запустить программу
python main.py

# Запустить тесты
pytest
```

При запуске `python main.py` выберите режим:

* `1` — автоматическая демонстрация сценария на заранее заданных заявках
  (по умолчанию, если просто нажать Enter);
* `2` — интерактивная регистрация участника с вводом данных.

Требования к окружению: Python 3.10+, пакет `pytest` для запуска тестов.
