# Ответы на контрольные вопросы ПР2

Ответы сопровождаются указанием на участок кода индивидуального проекта
«Система организации дискуссионных клубов»: на демонстрации достаточно
открыть указанный файл и показать соответствующие строки.

## По коллекциям, циклам и функциям

**1. Какие виды коллекций Python вы знаете? Для каких задач предназначен
каждый из них?**

* `list` — упорядоченная изменяемая коллекция; используется, когда важен
  порядок и состав меняется. Пример проекта: список регистраций `registrations`
  (`registrations.py`), список записей в JSON-файле (`storage.load_json()`).
* `tuple` — упорядоченная неизменяемая коллекция; подходит для фиксированных
  наборов значений. Пример проекта: `LEVELS` в `topics.py`,
  `PLACEHOLDING_STATUSES` и `STATUS_PLANNED/STATUS_RUNNING/STATUS_FINISHED` в
  `events.py`, `EVENT_FORMATS`, `MENU_ITEMS`, `DEMO_APPLICATIONS` в `main.py`.
* `set` — неупорядоченная коллекция уникальных элементов; применяется для
  проверки принадлежности и устранения повторов. Пример проекта:
  `PLACEHOLDING_STATUSES` (`events.py`) и множество тегов одной темы при
  сравнении в `topics.find_topics_by_tag()`.
* `dict` — коллекция пар «ключ – значение»; используется, когда элементы нужно
  находить по смысловому идентификатору. Пример проекта: `clubs`, `topics`,
  `events` — словари, где ключом является идентификатор записи.

**2. Чем список отличается от кортежа?**

Список изменяемый: к нему можно добавлять, удалять и заменять элементы
(`registrations.append(record)` в `registrations.create_registration()`).
Кортеж неизменяемый: создаётся один раз и не изменяется, поэтому в нём удобно
хранить фиксированные наборы — например, статусы, которые занимают место
(`PLACEHOLDING_STATUSES`), или пункты меню (`MENU_ITEMS`). Ещё одно отличие:
элементы кортежа могут повторяться и быть разных типов, как и элементы списка,
но сам кортеж можно использовать как ключ словаря, а список — нельзя.

**3. В каких случаях удобно использовать множество?**

Когда важна уникальность элементов и быстрая проверка принадлежности. В
проекте множество используется в двух местах:

* кортеж-константа `PLACEHOLDING_STATUSES = (STATUS_CONFIRMED,
  STATUS_ATTENDED)` — по нему проверяется, какие регистрации занимают место, в
  `events.count_active_registrations()`;
* в `topics.find_topics_by_tag()` теги темы приводятся к множеству нижнего
  регистра `{value.lower() for value in topic["tags"]}`, поэтому проверка тега не
  зависит от регистра и от повторов.

**4. Почему словари называются коллекцией пар «ключ – значение»?**

Словарь хранит набор пар: ключ и соответствующее ему значение. Ключ уникален и
позволяет получить значение напрямую, без перебора: `events[event_id]`, то есть
`clubs.get(club_id)`. В проекте ключ — идентификатор записи (`1`, `2`, …), а
значение — словарь с данными: у клуба это `name`, `description`, `moderator`,
у мероприятия — `club_id`, `topic_id`, `event_date`, `capacity` и другие поля.
Такой выбор сделан по правилу выбора коллекции: порядок записей не важен, а
нужен быстрый поиск по идентификатору.

**5. Чем цикл `for` отличается от цикла `while`?**

`for` перебирает элементы коллекции, и число повторений определяется самой
коллекцией: например, `for event_id in sort_events_by_date(events)` в
`print_event_card()` и `for club_id in sort_club_ids_by_name(clubs_data)` в
`show_clubs()`. `while` повторяет действия, пока условие истинно, и
применяется, когда число повторений заранее неизвестно: цикл меню `while True:`
в `run_menu()`, повтор запроса при неверном вводе в `input_int()` и
`input_date()`, ожидание существующего идентификатора в `input_event_id()`.

**6. Для чего используется функция `range()`?**

`range()` формирует последовательность целых чисел и используется, когда нужно
повторить действие заданное число раз: `for number in range(23)` в фикстуре
`tests/conftest.py` создаёт 23 регистрации, `range` применяется при
инициализации `1` по умолчанию и в других циклах с известным числом повторений.
Диапазон `range(a, b)` не включает правую границу.

**7. Как организовать перебор элементов словаря в цикле?**

При переборе `for key in dictionary` получаются ключи, а
`for key, value in dictionary.items()` — пары «ключ – значение». В проекте
используются обе формы: `for event in events.values():` и
`for topic in topics.values():` — когда нужны только данные, и перебор
идентификаторов с обращением `clubs_data[club_id]` — когда нужен доступ к
связанным записям (например, в `show_clubs()`). Порядок перебора задаётся
предварительной сортировкой: `for club_id in sort_club_ids_by_name(clubs_data)`.

**8. Для чего используются операторы `break` и `continue`?**

`break` немедленно прерывает текущий цикл, `continue` — переходит к следующей
итерации, пропуская оставшуюся часть тела цикла. В проекте `break`
используется в `run_menu()` для выхода из цикла меню по пункту `0`, а
пропуск записей применяется в `storage.load_events()`: запись с неверной датой
не добавляется в словарь, и цикл переходит к следующей.

**9. Как объявить функцию в Python? Что возвращает функция без оператора
`return`?**

Функция объявляется ключевым словом `def`: сначала имя, затем параметры в
скобках,
после чего двоеточие и тело с отступом:
`def get_free_places(current_participants: int, capacity: int) -> int:`.
Функция без `return` ничего не возвращает — её результат равен `None`.
Примеры: `main.show_clubs()` только печатает данные и ничего не возвращает, а
`clubs.add_club()` возвращает идентификатор созданного клуба. Функция может
завершиться досрочно оператором `return`, как `load_json()` возвращает пустой
список при ошибке чтения файла.

**10. Чем позиционные параметры отличаются от именованных?**

Позиционный параметр передаётся по порядку, именованный — по имени:
`print_event_card(event_id, events_data, clubs_data, topics_data,
registrations_data, today)` вызывается позиционно, а
`process_application(registrations_data, event, name, age_text, level,
read_text, DEMO_TODAY)` — с указанием имён последних параметров. Имена
делают вызов понятным и позволяют не учитывать порядок. Значения по умолчанию
(`today=None`, `limit=5`) всегда идут после обычных параметров.

**11. Что такое область видимости переменной?**

Это множество мест, где имя переменной доступно. Локальные переменные функции
существуют только внутри неё и извне не видны; глобальные доступны во всём
модуле; имена констант модулей в проекте записаны заглавными буквами. В проекте
принцип соблюдается явно: модули `clubs.py`, `topics.py`, `events.py`,
`registrations.py`, `analytics.py` не обращаются к глобальным данным
`main.py`, а получают коллекции параметрами. Имена, начинающиеся с `_`,
считаются внутренними и не показываются в выдаче интроспекции
(`run_introspection()`).

**12. Что такое `docstring` и для чего он нужен?**

`docstring` — строковый литерал в начале модуля или функции, описывающий её
назначение, параметры и результат. Он доступен программно через
`__doc__` и `inspect.getdoc()`, поэтому используется как документация и при
интроспекции: в режиме 4 программа выводит первую строку описания каждой
функции. Все модули и функции проекта снабжены `docstring`.

## По модулям, исключениям и файлам

**13. Что такое модуль Python?**

Модуль — файл с расширением `.py`, содержащий определения функций, констант и
других объектов; он подключается инструкцией `import`. В проекте модулями
являются `clubs.py`, `topics.py`, `events.py`, `registrations.py`,
`storage.py`, `analytics.py`, `utils.py` и `main.py`. Разделение по смыслу
делает программу обозримой: каждый файл отвечает за свою часть функциональности.

**14. Чем импорт модуля отличается от импорта отдельного объекта из модуля?**

`import analytics` подключает модуль целиком, и обращение выполняется через
имя модуля: `analytics.percent(...)`. `from analytics import percent` подключает
только конкретный объект, и он доступен сразу: `percent(...)`. В `main.py`
использованы оба варианта: модули импортируются целиком, когда нужны их
константы и когда модули передаются в `PROJECT_MODULES` для интроспекции
(`clubs`, `topics`, `events`, `registrations`, `analytics`, `storage`), а
конкретные функции импортируются поимённо. Форма `import *` в проекте не
используется: она делает неясным происхождение имён и мешает линтеру.

**15. Что такое пакет и для чего нужен файл `__init__.py`?**

Пакет — каталог с модулями, объединёнными общим именем и импортируемый
инструкцией `import имя_пакета.модуль`. Файл `__init__.py` делает каталог
пакетом, задаёт его интерфейс и может выполнять общий для модулей код.
В проекте пакет один — сам каталог проекта; его модули импортируются по
имени файла (`import storage`). Каталог `tests/` — не пакет: в нём нет
`__init__.py`, а общие фикстуры вынесены в `tests/conftest.py`, который pytest
загружает автоматически.

**16. Для чего используется конструкция `try/except`?**

Чтобы перехватить исключение и завершить сценарий предсказуемо, не прерывая
программу аварийно. В `utils.input_int()` перехватывается `ValueError` при
неверном числе, в `utils.input_date()` — `ValueError` при неверном формате
даты, в `main.process_application()` — `TypeError` и `ValueError` при
преобразовании возраста, в `storage.load_json()` — `FileNotFoundError`,
`json.JSONDecodeError` и `OSError`, в `storage.load_events()` — `ValueError` и
`TypeError` для записи с неверной датой, в `storage.save_json()` — `OSError`,
в `main.main()` — `EOFError` и `KeyboardInterrupt`.

**17. Чем блок `finally` отличается от блока `else`?**

Блок `else` выполняется, только если в `try` не возникло исключения, а блок
`finally` выполняется всегда — при успехе и при ошибке. В проекте `else` и
`finally` не применены: состояние файла гарантирует контекстный менеджер
`with`, поэтому достаточно обработать исключения и продолжить работу.

**18. Для чего используется оператор `raise`?**

`raise` сообщает об ошибке явно: выбрасывает указанное исключение, чтобы
вызывающий код его обработал. В `utils.parse_user_date()` неверный формат
приводит к исключению `ValueError`, которое перехватывает `input_date()` и
показывает пользователю сообщение вместо аварийного завершения. То же верно
для `parse_date()` и `save_json()`: ошибка чтения или записи файла превращается
в `False` и понятное сообщение.

**19. Зачем закрывать файл после работы с ним?**

Закрытие освобождает ресурсы операционной системы и гарантирует, что данные
записаны полностью: при незакрытом файле часть записи может потеряться. Если
программа продолжает открывать новые файлы, незакрытые дескрипторы накапливаются
и на крупных объёмах данных работа становится ненадёжной.

**20. Какие преимущества даёт контекстный менеджер `with`?**

Конструкция `with` гарантирует закрытие файла даже при возникновении
исключения, освобождает код от повторяющихся вызовов открытия и закрытия и
делает область работы с ресурсом явной. В `storage.py` все операции с файлами
выполнены через `with`:

```python
with file_path.open(encoding="utf-8") as file:
    data = json.load(file)
```

и

```python
with file_path.open("w", encoding="utf-8") as file:
    json.dump(records, file, ensure_ascii=False, indent=2)
    file.write("\n")
```

## По расширенным возможностям языка

**21. Что такое интроспекция? Какие функции Python для неё используются?**

Интроспекция — исследование объектов во время выполнения программы: просмотр
состава модуля, сигнатур функций и их документации без обращения к исходному
коду. В проекте она реализована режимом 4 — функцией `main.run_introspection()`,
которая использует:

* `inspect.getmembers(module, inspect.isfunction)` — состав функций модуля;
* `inspect.signature(function)` — сигнатура функции;
* `inspect.getdoc(function)` — текст документации, первая строка которого
  выводится как описание.

Дополнительно отфильтровываются импортированные объекты по
`function.__module__ == module.__name__` и служебные имена, начинающиеся с `_`.
Режим применяется и при разработке: он показывает состав модуля без запуска
приложения.

**22. Что такое пространство имён?**

Пространство имён — это соответствие между именами и объектами, которые они
обозначают. Имена модулей образуют собственное пространство, локальные имена
функции — отдельное, вложенное в глобальное; поэтому разные функции могут
использовать одно и то же имя параметра, не мешая друг другу. В проекте это
видно на примере параметров: `clubs`, `events`, `registrations` — обычные
локальные имена функций, а `LEVELS`, `STATUS_PLANNED`, `MENU_ITEMS` —
константы модулей, к которым обращаются через имя модуля или через импорт.
Модули не зависят от глобальных данных `main.py`, поэтому пространства имён
разделены.

**23. Что такое итератор и генератор?**

Итератор — объект, который выдаёт элементы коллекции по одному, а генератор —
разновидность итератора, который сам создаёт эти значения по мере
востребования, не храня весь результат в памяти. В проекте генераторы
использованы там, где подходящие записи нужны последовательно:

* `events.iter_upcoming_events(events, today)` — выдаёт мероприятия, которые ещё
  не завершились, в порядке даты; вызывающий код превращает их в список только
  тогда, когда это действительно нужно: `list(iter_upcoming_events(...))`;
* `topics.filter_topics_by_level(topics, level)` — выдаёт темы выбранного
  уровня;
* `clubs.iter_club_names(clubs)` — последовательно выдаёт названия клубов в
  алфавитном порядке.

**24. Для чего используется оператор `yield`?**

`yield` превращает функцию в генератор: вместо единого результата она
выдаёт значение по требованию и при этом сохраняет своё состояние между
вызовами. Код после `yield` выполняется при следующем обращении к генератору.
Именно `yield` используется в `iter_upcoming_events()`: идентификатор очередного
мероприятия передаётся наружу, а перебор приостанавливается до того момента,
когда вызывающий код запросит следующий элемент.

**25. Что такое лямбда-функция и где она применяется?**

Лямбда-функция — короткая безымянная функция, задаётся выражением
`lambda аргументы: выражение`. Применяется там, где нужна небольшая функция
как значение, — прежде всего как ключ сортировки. В проекте:

* `events.sort_events_by_date()` — `key=lambda event_id: (events[event_id]
  ["event_date"], events[event_id]["start_time"])`;
* `clubs.sort_club_ids_by_name()` и `clubs.sort_club_ids_by_size()`;
* `topics.sort_topics_by_level()` — ключ обращается к словарю `LEVEL_ORDER`,
  поэтому порядок соответствует сложности темы, а не алфавиту;
* `analytics.get_top_participants()` — сортировка пар по убыванию активности.

## По качеству кода и тестированию

**26. Что такое аннотации типов и как они оформляются в сигнатуре функции?**

Аннотации типов — указания типов параметров и возвращаемого значения прямо в
сигнатуре функции. Они не влияют на выполнение, но делают соглашения о данных
явными и помогают обнаруживать ошибки. Пример проекта:

```python
def add_club(clubs: dict[int, dict], name: str, description: str,
             moderator: str) -> int:
```

Здесь `clubs` — словарь «идентификатор → данные клуба», имя и описание —
строки, результат — целое число. Для составного типа указывается обобщение
`list[dict]`, для произвольного — `Optional[dict]` и `Iterator[str]`.
Аннотации проставлены у основных функций всех семи библиотечных модулей.

**27. Для чего используется линтер `flake8` и как выполнить проверку кода
проекта?**

Линтер проверяет соответствие кода стандарту оформления PEP 8 и находит
проблемы до запуска программы: превышение длины строки, неиспользуемые
импорты и переменные, ошибки отступов, пустые строки. Проверка выполняется из
корня проекта:

```bash
flake8 .
```

или, если служебные каталоги исключены вручную:

```bash
python -m flake8 . --exclude=.git,__pycache__,.pytest_cache
```

Если замечаний нет, `flake8` не выводит ничего — это ожидаемый результат.
Сообщение линтера содержит имя файла, номер строки и код замечания, например
`events.py:180:80: E501 line too long (84 > 79 characters)`. Текущее состояние
проекта: проверка завершается без замечаний, код возврата — 0.

**28. Какие требования к оформлению кода предъявляются в рамках ПР2?**

* понятная структура программы: код разделён на модули по смыслу;
* осмысленные имена функций и переменных: имя отражает назначение
  (`count_active_registrations`, `find_topics_by_tag`, `next_id`);
* соответствие PEP 8: отступы, порядок импортов, длина строки не более
  79 символов, две пустые строки между функциями;
* отсутствие неиспользуемого кода: закомментированных фрагментов,
  неиспользуемых переменных и импортов;
* отсутствие дублирования: повторяющаяся логика выделяется в отдельную
  функцию;
* документирующая строка у каждого модуля и функции;
* аннотации типов у основных функций;
* никакого декораторов — они отнесены к ПР3.

Все модули имеют `docstring`, повторяющаяся логика вынесена в отдельные
функции (например, `resolve_event_data()`, `percent()`, `get_availability_text()`),
а импорт каждого модуля используется в коде.

**29. Как устроен автоматизированный тест `pytest` и что проверяет оператор
`assert`?**

Тест — обычная функция с именем, начинающимсяся на `test_`, которая вызывает
проверяемую функцию и завершается проверкой `assert`. Оператор `assert`
проверяет истинность выражения: если оно истинно, тест проходит, если ложно —
тест падает с указанием файла и строки. Проверяется ровно один сценарий на
функцию, как рекомендуется в методических указаниях.

Пример теста проекта:

```python
def test_get_registration_result_waiting_no_places():
    result, reason = get_registration_result(
        19, "средний", True, STATUS_PLANNED, 0, 16, "средний",
    )

    assert result == RESULT_WAITING
    assert "мест" in reason
```

Общие данные для тестов вынесены в фикстуры `tests/conftest.py`: пустые и
заполненные коллекции, список из 23 подтверждённых регистраций, временный
каталог данных (`tmp_path` и `monkeypatch`) и подмена ввода пользователя
(`answers`), благодаря которой проверяются диалоговые сценарии меню.

**30. Как запустить тесты проекта и как интерпретировать результат их
выполнения?**

Из корня проекта:

```bash
pytest
```

или подробно — с именами тестов и итоговой строкой:

```bash
python -m pytest -q
```

Результат интерпретируется по строке вида `159 passed in 0.34s`: все тесты
прошли, программа вернула код 0. Если тест не прошёл, выводится имя теста,
файл, строка и различие ожидаемого и фактического значения; такая проверка
выполняется только при `assert`. Результат текущего состояния проекта:

```
159 passed in 0.34s
```

**32. Как в проекте представлены данные (структуры, формат хранения)?**

Данные представлены словарями и списками: клубы, темы и мероприятия — словари,
где ключом является идентификатор записи, а значением — словарь с полями;
регистрации — список словарей. Хранятся данные в четырёх JSON-файлах каталога
`data/`: `clubs.json`, `topics.json`, `events.json`, `registrations.json`.
Каждый файл — список словарей с полем `id`, поэтому функция
`storage.records_to_dict()` превращает прочитанный список в словарь по
идентификатору, а `dict_to_records()` выполняет обратное преобразование перед
записью. Дата мероприятия хранится строкой в формате `ГГГГ-ММ-ДД` и при
загрузке превращается в объект `datetime.date`, чтобы даты можно было
сравнивать. Пример записи:

```json
{
  "id": 1,
  "event_id": 1,
  "name": "Мария К.",
  "age": 19,
  "level": "средний",
  "has_read_materials": true,
  "status": "подтверждён",
  "ticket_code": "DC-1037"
}
```

**33. Как устроена проверка доступности мероприятия?**

Проверка состоит из двух функций. `registrations.is_event_available(events,
registrations, event_id, today=None)` получает данные мероприятия, определяет
его статус по дате и, если мероприятие ещё не завершено, считает занятые места
и сравнивает их с вместимостью: место доступно, если

```python
get_free_places(signed_up, int(event["capacity"])) > 0
```

Занятые места считает `events.count_active_registrations()` — учитываются только
статусы из `PLACEHOLDING_STATUSES`, то есть подтверждённые заявки и отметки о
посещении; лист ожидания и отменённые заявки мест не занимают. Число свободных
мест вычисляется функцией `get_free_places()`, которая не возвращает отрицательное
значение. Результат проверки превращается в текст функцией ПР1
`get_availability_text(is_available)` — аналогом `get_booking_status()`
сквозного примера: `print(get_availability_text(is_available))`. Эта же
доступность учитывается при записи: функция `get_registration_result()`
возвращает лист ожидания, когда свободных мест нет.

**34. Какие исключения обрабатываются в программе и зачем?**

* `ValueError` — некорректный ввод числа или даты: `utils.input_int()`,
  `utils.input_date()`, `main.process_application()`, `storage.load_events()`;
* `TypeError` — неожиданный тип значения при преобразовании возраста
  (`process_application()`) или при разборе даты из файла (`load_events()`);
* `KeyError` — обрабатывается неявно через проверку наличия ключа: например,
  в `registrations.confirm_registration()` и `cancel_registration()` запись
  ищется циклом, а отсутствие мероприятия проверяется функцией
  `events.get_event()`; в `storage.records_to_dict()` записи без поля `id`
  пропускаются;
* `FileNotFoundError` — файл данных отсутствует: `storage.load_json()`
  сообщает об этом и возвращает пустой набор данных, поэтому программа
  запускается в чистом репозитории;
* `json.JSONDecodeError` — файл повреждён: сообщение с причиной и пустой набор
  данных;
* `OSError` — файл недоступен при чтении или записи: чтение возвращает пустой
  набор, запись возвращает `False`, и вызывающий код сообщает об ошибке;
* `EOFError` и `KeyboardInterrupt` — пользователь прервал работу или ввод
  исчерпан: `main.main()` завершает программу с сообщением.

Общий принцип: пользователь всегда получает понятное сообщение, а данные —
значение по умолчанию, программа не завершается аварийно.

**35. Какие модули входят в состав проекта и как распределена логика между
ними?**

Восемь модулей:

| Модуль | Назначение |
|--------|------------|
| `main.py` | Точка входа: выбор режима, меню, вывод данных, обработчики действий пользователя |
| `clubs.py` | Клубы: добавление, получение, поиск по подстроке, сортировки, карточка |
| `topics.py` | Темы дискуссий: уровни сложности, теги, отбор по уровню и тегу, карточка |
| `events.py` | Мероприятия: статусы, свободные места, сортировка по дате, генератор предстоящих, карточка, статусы регистраций |
| `registrations.py` | Регистрации: проверка требований, решение по заявке, код участия, доступность, подтверждение и отмена |
| `analytics.py` | Статистика: сводка по мероприятиям, счётчики по клубам и уровням, рейтинг участников, оформление таблиц |
| `storage.py` | Файлы: чтение и запись JSON, преобразование списков и словарей, загрузка и сохранение проекта |
| `utils.py` | Общее: безопасный ввод с повтором запроса, работа с датами, генерация идентификатора |

Логика распределена так, чтобы модули не дублировали друг друга и не создавали
циклов импорта: модули данных не обращаются к файлам, файловый модуль не знает
остальных, `analytics.py` только читает коллекции, а `main.py` связывает всё
вместе. Общее для `events.py` и `registrations.py` — модуль `utils.py`,
поэтому цепочка импорта остаётся однонаправленной.

**38. Почему данные проекта хранятся в файлах, а не в переменных
программы?**

* сохранность между запусками: данные, добавленные пользователем, не исчезают
  при завершении программы, — именно это и требуется от системы учёта;
* независимость данных от кода: коллекции передаются в функции параметрами, а
  не создаются внутри них, поэтому одни и те же функции работают и с данными
  из файла, и с данными теста;
* масштабируемость: файл JSON заменяется на базу данных без изменения
  предметной логики — на ПР7–ПР9 Django и ORM подключаются вместо файлов;
* целостность и единый формат: формат JSON задаёт правила хранения полей и
  позволяет проверить данные до загрузки;
* удобство отладки и контроля: файл можно открыть и посмотреть содержимое,
  не запуская программу.

Именно поэтому загрузка и сохранение сосредоточены в модуле `storage.py`, а
остальные модули работают с коллекциями и ничего не знают о файлах.
